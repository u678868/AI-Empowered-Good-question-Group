五、设计说明与限制
--------------------------------------------------------------------------------
1. 绳索长度采用端点间的环境三维直线距离（Rope.length_3d，符合规范定义的字段）；
2. 在默认环面（ring 130）上，单段 30 m 只能覆盖很小的参数窗口，因此三根绳索构成的
   闭合小三角形角盈约 0.01 度，无法达到 Quest 1 的 186.4 度目标；这是"有限绳索"与
   超大流形尺度共同决定的诚实结果。Quest 1 的完成路径为 Protractor + 3 个标记桩
   （规范允许"或 3 个闭合相连的标记点构成的三角形"），后端测试已覆盖该完成流程；
3. 障碍物端点必须在当前视距内，服务端显式校验，避免通过绳索长度探测未探索区域；
4. 学院任务书与推导弹窗只展示任务/几何信息，不含出口坐标或真实距离；
5. 动画仍为规范要求的占位级几何动画。

现象：
1. 使用绳索提示 unknown tool（'rope_connect'）；
2. 任务未完成时右侧探测器仍返回真实 signal / Weak。

排查与根因（已在终端复现确认）：
- 本机 8000 端口当时存在两个**陈旧服务进程**（PID 27528 / 55220），其 Python 代码是
  Task 18 时期版本：
    * GET /api/state/player 不含 detector_locked / ropes / rope_remaining（有 quest）；
    * signal=0.137798 / label=Weak（未封印）；
    * POST /api/action/tool {"tool":"rope_connect",...} 返回 400
      {"error": "unknown tool 'rope_connect'"}。
- 浏览器静态文件每次请求都从磁盘读取（因此前端是新的），但后端是旧进程 → 出现
  "新前端 + 旧后端" 的组合：前端发送 rope_connect，旧后端不认识；旧后端不返回
  detector_locked，前端因此认为探测器未被封印 → 两个现象完全吻合。

修复动作：
1. 结束 8000 端口上的所有陈旧监听进程（PID 27528、55220）；
2. 用当前代码重新启动 8000 服务（隐藏窗口）：
   .venv\Scripts\python.exe -m src.main --serve --port 8000 --debug
3. 重新验证：
   - GET /api/state/player → detector_locked=True、ropes=[]、rope_remaining=100.0、
     label=Sealed、signal=0.0；
   - POST rope_connect（无标记时）→ 400 {"error": "unknown marker 'A'"}，
     证明已进入绳索分支（不再是 unknown tool）；
   - 浏览器（http://127.0.0.1:8000/?v=task19fix）：
     #toolbar 元素数 0；探测器读数 "signal 0.0000 (Sealed, same)"；
     点击封印探测器 → 左上角提示 "The exit detector is sealed by the academy geometric
     trial. Complete the quests to unlock it."；控制台无报错。

结论：本轮两个 bug 均为**陈旧后端进程**导致，并非前端变量名不一致；代码本身已正确。

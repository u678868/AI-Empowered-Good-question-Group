一、任务目标
--------------------------------------------------------------------------------
1. 多级等比地图缩放：S in {0.5, 1.0, 2.0, 4.0, custom 0.2-10.0}，通过物理感知的
   1/S 缩放（步长 / 视距 / 障碍物半径与安全边距 / 捕获半径）实现，参数空间与流形
   方程完全不动、不重新采样；
2. 三阶难度：Easy（默认，探测器可用）、Medium（剥离距离探测器，依赖 Eye、曲率仪、
   测角仪与标记点）、Hard（[Reserved / Work in Progress] 安全占位）；
3. 计分占位：维护 elapsed_time、effective_steps（Σ 1/speed_scale）、tool_usages
   （detector/pointer/curvature/triangle/marker）与 calculate_score()（当前返回 0）；
   Web HUD 与胜利弹窗显示 Score: 0 / Final Score: 0。

四、设计要点（与规范逐条对应）
--------------------------------------------------------------------------------
- 缩放律：step=base/S、R_view=base/S、r_obs=base/S、r_capture=base/S；参数空间与
  流形方程不变。Small(0.5) 视野更广、移动更快；Large(4.0) 视野更窄、行进旷远。
- Medium 静默在 gameplay 层与 server 层双重生效：玩家可见的 read/peek/marker 与
  scan 工具都只返回 signal 0.0 / Offline / same，杜绝通过信号爬山；
- Hard 与 Medium 一样不提供距离线索，但额外带 difficulty_reserved=true，作为
  后续动力系统/引力源的扩展槽位；
- 计分输入真实累计（effective_steps 含上坡 1/speed_scale 加权），score 仍为 0 的
  显式占位，方便后续替换公式而不改动接口。

六、已知限制
--------------------------------------------------------------------------------
1. calculate_score() 目前固定返回 0（规范要求占位），尚无评分公式；
2. Hard 为 Reserved 占位：行为等同"静默 + 允许移动"，没有额外动力/引力机制；
3. 按规范只缩放 step/view/obstacle/capture 四项，detector_scale 与 pointer_sectors
   不随 S 变化；
4. Medium 的标记点 signal/label 为中立值（signal 0.0 / Weak），不携带距离信息；
5. 本地客户端在缩放地图上的移动速度与服务器步长仍按同一 1/S 律（playwright 后台
   标签页 rAF 降频时自动化移动会偏慢，真实聚焦游玩为 60FPS）。
